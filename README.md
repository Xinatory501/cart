# CartaMe Support Bot — Платформа поддержки пользователей

Многорегиональная платформа чат-ботов поддержки пользователей для Беларуси (BY), Казахстана (KZ) и Узбекистана (UZ), работающая на единой кодовой базе. Проект доработан и полностью соответствует спецификации **ТЗ v1.2** (все 60 пунктов).

---

## 🚀 1. Как быстро запустить проект

### Подготовка `.env`
Создайте файл `.env` в корне проекта на основе вашего конфигурационного профиля.

Пример заполнения:
```env
# Идентификация экземпляра
INSTANCE_ID=cartame_by
CLIENT_CODE=CARTAME
REGION_CODE=BY
PROJECT_TYPE=BUSINESS

# Telegram
ADMIN_IDS=821315597
BOT_TOKEN=ваш_токен_первого_бота
SUPPORT_GROUP_ID=-1004324100394

# База данных
DATABASE_URL=sqlite+aiosqlite:///./data/bot.db

# Логирование и безопасность
LOG_FORMAT=text
LOG_LEVEL=INFO
SECRET_ENCRYPTION_KEY=сгенерированный_ключ_fernet
CORS_ALLOWED_ORIGINS=http://localhost:3000
```

### Запуск через Docker (Рекомендуемый)
Убедитесь, что у вас установлен Docker и запущен Docker daemon.

```bash
# 1. Запуск и сборка контейнеров в фоновом режиме
docker compose up -d --build

# 2. Просмотр логов в реальном времени
docker compose logs -f

# 3. Перезапуск бота после изменения .env
docker compose restart
```

### Локальный запуск (для разработки)
```bash
# 1. Создание виртуального окружения
python3 -m venv .venv
source .venv/bin/activate

# 2. Установка зависимостей
pip install -r requirements.txt

# 3. Запуск бота
python3 bot.py
```

## 💾 2. База данных и миграции (SQLite ➡️ PostgreSQL)

Бот поддерживает работу как с **SQLite** (для локальной разработки), так и с **PostgreSQL** (для продакшена).

### Переключение на PostgreSQL:
1. Раскомментируйте библиотеки `asyncpg` и `alembic` в файле [`requirements.txt`](file:///requirements.txt).
2. Раскомментируйте блок сервиса `postgres` в [`docker-compose.yml`](file:///docker-compose.yml) при необходимости поднять БД в докере.
3. Измените строку подключения в `.env`:
   ```env
   DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/db_name
   ```
4. Бот при старте автоматически определит PostgreSQL, включит пул соединений (размер: 5, переполнение: 10) и инициализирует схему данных.

### Как работает автомиграция:
При обновлении проекта на сервере вам **не нужно стирать существующую базу данных** SQLite или PostgreSQL.
* В метод `init_db()` встроен механизм **программной самомиграции**.
* На старте бот проверяет структуру и безопасно добавляет новые колонки (например, `media_type` и `file_id` для вложений в таблицу `chat_history`), не повреждая существующие переписки и настройки.
* На сервере достаточно выполнить:
  ```bash
  git pull origin main
  docker compose up -d --build
  ```

### 🔑 Интеграция с HashiCorp Vault (ADM-04):
Бот поддерживает **гибридное шифрование секретов at rest** с интеграцией с **HashiCorp Vault Transit Engine**:
* Если в `.env` указаны переменные `VAULT_ADDR` и `VAULT_TOKEN`, бот использует Vault в качестве внешнего криптографического провайдера (Transit Secrets Engine). Данные шифруются внешним ключом, а в БД сохраняется зашифрованный текст с префиксом `vault:`.
* Если переменные не заданы, бот плавно переключается (fallback) на локальное симметричное шифрование через библиотеку `cryptography.fernet` с использованием ключа `SECRET_ENCRYPTION_KEY` из `.env` (префикс `enc:` в БД).
* Это обеспечивает бесшовную миграцию: старые ключи продолжат расшифровываться локально, а новые будут защищаться через Vault.

## ⚠️ 3. Что НЕ смогли реализовать (Исключенные из локального контура фичи)

Некоторые интеграции и внешние системы вынесены за рамки кода приложения и не реализуются внутри бота, так как требуют выделенной инфраструктуры:

1. **Терминация TLS/HTTPS (WEB-07):** Настройка шифрования трафика SSL/TLS не вшивается в Python-код контейнера. Это должно настраиваться на уровне внешнего обратного прокси (Nginx, Traefik, Cloudflare).

## ✅ 4. Что реализовали (Фичи ТЗ v1.2)

### 🎫 Управление кейсами и вложениями (TG-06, ADM-18)
* **6-значный тикет:** Генерация уникальных случайных кодов обращений с защитой от коллизий.
* **Вложения пользователя:** Фото, документы, видео, голосовые и стикеры автоматически пересылаются в тему поддержки, а ИИ выключается, передавая диалог оператору.
* **Вложения оператора:** Оператор может отправлять медиафайлы обратно пользователю.
* **Экономия диска:** Медиа сохраняются в виде `file_id` Telegram прямо в БД, исключая переполнение диска.

### ⭐ CSAT и Отчетность
* Вывод оценки 1⭐–5⭐ в меню пользователя после закрытия кейса.
* Связывание оценки с сессией и оператором для аналитики.
* Web-интеграция: API для сохранения оценок и диалогов.

### 🤖 ИИ и База знаний
* **Семантический поиск (RAG - AI-09):** Полноценный векторный поиск по базе знаний на базе косинусного расстояния (cosine similarity) с автогенерацией эмбеддингов через используемого ИИ-провайдера. Включает автоматическое ленивое кэширование эмбеддингов в БД и умный текстовый фоллбэк при отсутствии связи.
* **PII Masking (AI-11):** Автоматическое вырезание номеров телефонов, email, банковских карт и ИИН перед отправкой запроса к LLM.
* **ИИ-Черновики (OPS-11):** Команда `/hint` в топике поддержки генерирует черновик ответа оператору на основе контекста беседы.
* **Typing Indicator (AI-13):** Отображение статуса «печатает...» в Telegram при генерации ответа.

### ⏱ SLA и График работы
* Задание дедлайна SLA при создании сессий. Фоновый мониторинг шлёт предупреждения за 30 минут до нарушения и алертит при овертайме.
* Настройка рабочих часов, праздников и часовых поясов прямо через панель управления в Telegram с записью в БД.

### 🔐 Безопасность и Эксплуатация
* **RBAC:** Роли доступа (user, operator, supervisor, project_admin, superadmin).
* **Admin Middleware:** Блокировка несанкционированных обращений к `admin_` callback-запросам.
* **GDPR Erasure:** Полное стирание переписки и анонимизация пользователя по запросу «Право на забвение».
* **Task Registry:** Реестр фоновых тасок с graceful shutdown для предотвращения утечек памяти при остановке.
* **JSON-Логи:** Поддержка структурированного JSON-логирования для Kibana/Grafana при `LOG_FORMAT=json`.
